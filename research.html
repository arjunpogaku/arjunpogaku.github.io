Turning Traffic Data into Queryable Knowledge Graphs

Large-scale transportation networks continuously generate massive spatiotemporal data — most research just predicts what happens next. This work builds a symbolic knowledge graph that captures why, and a domain-constrained LLM that lets you ask it directly.

Most traffic research chases better predictions. This work asks what happens if the data can explain itself.

How it works

01 · data

Spatiotemporal data

High-frequency, multivariate congestion readings across a road network, hour by hour.

→
02 · graph

Symbolic construction

Deterministic rules translate readings into nodes and edges — spatial, temporal, and congestion-level relationships.

→
03 · rules

Domain knowledge base

Schema constraints, domain rules, and exemplar queries ground the system in what's actually true about the graph.

→
04 · query

DKB-assisted LLM

Constrained generation produces valid Cypher instead of guesses — schema-aware and rule-checked.

→
05 · answer

Natural language

Results return as plain-language answers, traceable back to the exact graph relationships that produced them.

Why interpretability matters: a purely predictive model tells you traffic will be bad — not why, or where the pattern came from. By grounding every query in an explicit graph of spatial, temporal, and congestion relationships, each answer traces back to the data that produced it. In evaluation on real-world traffic data, the DKB-assisted LLM produced significantly more accurate and relevant answers than general-purpose LLMs prompted directly on the same data.
